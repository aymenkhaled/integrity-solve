Critical Bug 1 - Frontend API Response Shape Is Wrong
The shared frontend API helper already unwraps the server response:

File: client/src/lib/api.ts

Current pattern:

const data = (await res.json()) as ApiResponse<T>;
if (!data.ok) { ... }
return data.data;
This means:

casesApi.list() returns Case[], not { data: Case[] }
casesApi.summary(id) returns CaseSummary, not { data: CaseSummary }
wizardApi.start(...) returns a WizardRun, not { data: WizardRun }
wizardApi.saveStep(...) returns { run, routeResult }, not { data: { run, routeResult } }
The new pages currently treat the already-unwrapped response as if it still has another .data property. This is likely why creating a case appears to work but the case list stays empty or the detail page says not found.

Fix all new case/wizard pages to use the actual unwrapped values.

Required Fixes In CasesPage.tsx
Current broken pattern:

const { data } = useQuery<{ data: Case[] }>({
  queryKey: ['cases'],
  queryFn: () => casesApi.list() as Promise<{ data: Case[] }>,
});

const caseList = data?.data ?? [];
Replace with the correct pattern:

const { data: cases = [], isLoading, error } = useQuery<Case[]>({
  queryKey: ['cases'],
  queryFn: () => casesApi.list() as Promise<Case[]>,
});

const caseList = cases;
Also add a visible error state if the query fails. The user must not see "No cases yet" when the API actually failed.

const { data: summary, isLoading, error } = useQuery<CaseSummary>({
