13. High-Impact Features for Later
These features should be mentioned as future differentiation, not included in Milestone 1.
- Case Story / Audit Narrative: a human-readable explanation of service, party, checks,
result, decision, and reason.
- Provider Cost Simulator: estimate Didit cost before running checks based on workflow and
party count.
- Compliance Evidence Pack: export a regulator-ready pack with documents, decisions,
training, checks, and audit trail.
- Compliance Debt Score: show overdue reviews, unresolved escalations, stale program
sections, and missing evidence.
- Program Diff / Review Pack: show what changed when AML program data is updated.
- Weekly Compliance Pulse: short dashboard/email summary of urgent items and completed
compliance progress.
- Reusable Verified Party Graph: reuse legally safe verified UBO/officer/person data across
related cases.
- Smart Ongoing Monitoring: scheduled re-screening, review due dates, ownership changes, and
monitoring alerts.
- Client-Facing CDD Portal: branded external link for customers to submit CDD, BO, and
source-of-funds information.

Milestone title
Integrity Solve AML/CTF Portal - Wizard-led Flow + Didit-ready Integration Proof

Milestone description
Use the existing prototype as a foundation and build a focused proof of one program-side wizard
flow and one transaction/CDD wizard flow. The milestone will demonstrate guided question flow,
conditional routing, recommended verification/screening steps, Didit-ready check
request/session handling, webhook/result capture pattern, a simple case summary/PDF output, and
audit trail events.
Deliverables to list on Upwork
- One program-side wizard proof for business profile and designated service applicability.
- One transaction/CDD wizard proof for designated service, party type, risk triggers,
recommended checks, and escalation path.
- Minimal backend/data layer for cases, wizard progress, check requests, webhook events,
normalized results, audit logs, and case outputs.
- Didit-ready integration shell using mock mode first, with configuration for sandbox/live
mode when credentials are provided.
- Webhook receiver pattern with signature verification, duplicate protection, result
normalization, and case update logic.
- Readable case summary and basic PDF/case output foundation.
- Short handover note listing what is done, what is mocked, and what needs Daniel/Didit
confirmation.
Acceptance wording
Milestone is complete when Daniel can review a working guided program flow and a working guided
transaction/CDD flow, see a mock or sandbox Didit-style result return into the case, view the
audit trail, and generate a basic case summary/PDF output.
Out-of-scope wording
- This milestone does not include the full production platform.
- This milestone does not include final AML/CTF legal advice or legal responsibility for
rule wording.
- This milestone does not include full Stripe billing/subscription implementation.
- This milestone does not include complete role/permission coverage for every user type.
- This milestone does not include production Didit launch unless Daniel provides all
required credentials, workflow IDs, payload samples, and approvals.
- This milestone does not include full document template production, evidence retention
policy, penetration testing, or security audit.
Change control wording
Any request outside the listed deliverables should be handled as a written scope change or a
new milestone. This keeps the first paid stage focused, reviewable, and fair for both sides.
