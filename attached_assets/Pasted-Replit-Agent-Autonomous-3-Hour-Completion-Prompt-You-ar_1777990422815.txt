Critical Bug 1 - Frontend API Response Shape Is Wrong
The frontend API helper already unwraps the server response.

File: client/src/lib/api.ts

Current pattern:

const data = (await res.json()) as ApiResponse<T>;
if (!data.ok) {
  const err = new ApiError(data.error.message, data.error.code, data.error.field);
  throw err;
}
return data.data;
Therefore:

casesApi.list() returns Case[], not { data: Case[] }.
casesApi.summary(id) returns CaseSummary, not { data: CaseSummary }.
wizardApi.start(...) returns WizardRun, not { data: WizardRun }.
wizardApi.saveStep(...) returns { run, routeResult }, not { data: { run, routeResult } }.
diditApi.createSession(...) should return whatever is inside the server's data.
The new case/wizard pages currently treat responses as double-wrapped. This makes the case list look empty and detail/wizard flows break.

Fix CasesPage.tsx
Broken pattern:

const { data } = useQuery<{ data: Case[] }>({
  queryKey: ['cases'],
  queryFn: () => casesApi.list() as Promise<{ data: Case[] }>,
});

const caseList = data?.data ?? [];
Correct pattern:

const {
  data: cases = [],
  isLoading,
  error,
} = useQuery<Case[]>({
  queryKey: ['cases'],
  queryFn: () => casesApi.list() as Promise<Case[]>,
});

const caseList = cases;
Add visible error state. Do not show "No cases yet" when the API failed.
